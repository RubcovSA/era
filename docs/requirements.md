Allotted time 8 hours 

1-Day Build Assignment — “Build Something Cool”

Context

ErateSync builds software for schools, libraries, service providers, and manufacturers operating in the E-rate ecosystem. Our core advantage comes from deeply understanding customer pain points and turning public E-rate / USAC data into tools that create real leverage for users.

We’re looking to understand how you think, how you build, and how you use AI as leverage — not whether you can follow a spec.

The Challenge

Build something cool in one day.

That’s it.

Rules (non-negotiable)
1. Must use E-rate / USAC public datasets
• Any relevant USAC Open Data (Form 470, FRN, funding, C2, etc.)
2. Must NOT replicate or extend an existing ErateSync feature
• This should be net new, not a clone
3. Must be based on our ICP / Customer Pain Points doc
• Pick one or more real problems customers have
4. Time-boxed to ~6–8 hours
• We care about judgment under constraint, not perfection
5. Use any AI agent(s) you want
• Claude, ChatGPT, Cursor, Copilot, scripts, whatever
• “Cheating” is encouraged

You decide:
• which pain point to solve
• who the user is
• what “cool” means
• what to ignore


What “Cool” Means (guidance, not requirements)

By “cool,” we mean something that:
• clearly maps to a real customer pain
• uses E-rate data in a non-trivial, thoughtful way
• would make a user say “oh wow, that’s actually useful”
• can be explained in under 5 minutes
• shows taste for UX, even if rough

This can be:
• a small UI
• a script + visualization
• a lightweight web app
• a CLI + output
• anything that ships value


Deliverables

1. Code
• GitHub repo or PR (public or private is fine)
• Any stack

2. Loom video (5–10 minutes)

Walk us through:
• what you built
• who it’s for
• why you chose this problem
• how it works
• what you’d do next with more time

3. AI agent record
• Screenshots, exports, or recordings of your AI sessions
• We want to see how you work with AI, not just the output

4. Short README (max ~1 page)

Include:
• the problem you chose (from the ICP doc)
• assumptions you made
• tradeoffs you consciously accepted
• what you intentionally did not build

5. Validation
• Show at least 3–5 different data scenarios
• different entities
• different funding years
• edge cases (no data, lots of data, weird data)

Screenshots or outputs are fine.


What We’ll Talk Through After

On a follow-up call, you’ll:
• walk us through your decisions
• explain how you used AI (and where you overrode it)
• explain what surprised you
• explain what you’d ship next if this were production



What We’re Evaluating (be transparent)

We are not scoring on polish.

We are evaluating:
• Agency – did you move without a spec?
• Speed – did you ship something real in a day?
• Judgment – what did you choose to build vs ignore?
• Customer empathy – does this solve an actual pain?
• Data thinking – did you validate across cases?
• AI leverage – did you use AI to move faster?
